# AiDrama 战略路线图（2026-07，/ev R10 L5 轮）

> 本文档是一次抬头看路的战略盘点，基于 R1-R9 进化轮与全部提交历史。下一次 L5 复盘建议在 R30 前后或重大里程碑时进行。

## 1. Where are we?（现状定位）

**阶段判断：MVP 后期 → 单人可用的成长期早期。**

- 核心流水线已闭环：剧本改写 → 角色/场景提取 → 分镜拆解 → 出图 → 出视频 → 缺陷检查/重生成 → 合并导出。
- 已具备商业化雏形：登录注册、用户数据隔离、钱包、支付宝充值、按时长计费结算。
- 已能上线运行：SCF Web 函数部署、COS 存储、ffmpeg 层、webhook 异步回调。
- 工程质量刚完成一轮系统性收紧：前后端 strict TypeScript 满配、390+29 个纯策略单测、路由策略层（policies）模式成型。

**一句话定位：这是一个"AI 短剧生产工作台"，当前壁垒在流水线编排质量，而非任何单点 AI 能力。**

## 2. What's working?（被验证的决策）

| 决策 | 验证依据 |
| --- | --- |
| 纯策略函数 + 单测、路由只做接线 | 390 个后端测试全绿零 DB 依赖，重构（如 R9 probe 提取）成本极低 |
| 多 provider 适配矩阵（vidu/ali/volcengine/minimax/gemini/openai…） | provider 更迭频繁，适配层让切换成本可控；probe 探测让配置可自检 |
| 提示词工程下沉为可测策略（chapterShotMediaPolicy 等） | 视频连贯性守护栏（结束画面约束、参考素材绑定编号）可回归测试，质量迭代不靠玄学 |
| 先计费后消费 + webhook 结算补偿（billing_required 挂起） | 多次 billing 修复后收敛稳定，是商业化的地基 |
| 缺陷检查 + 自动重生成闭环 | AI 视频废片率高，这是产品级体验和 demo 级玩具的分界线 |

## 3. What's not?（技术债与偏航）

- **routes/resources 层 CRUD 接线无测试**（11 文件 0 测试）：接受。纯接线，出错概率低，E2E 冒烟覆盖即可，不值得攻。
- **单体 Hono + SCF 冷启动/冻结特性的张力**：多实例冻结导致轮询任务和内存态任务不可靠，webhook 是唯一可信回调路径。该债要"接受并顺势设计"——一切长任务必须走 webhook/DB 状态机，不允许新增内存态轮询。
- **db/index.ts 顶层 await 连接 MySQL**：阻碍 app 级集成测试。中期值得还（惰性连接或注入），但优先级低于产品主线。
- **合并导出对 ffmpeg 版本敏感**（xfade 7.x CFR 问题已修）：持续风险点，任何 ffmpeg 层升级必须过 merge E2E。
- **文档债基本清零**（R8），无需再投入。

## 4. Where to go?（未来 3-6 个月最值得投入的 3 件事）

按优先级排序：

1. **成片质量与一致性（护城河所在）**
   - 角色/场景跨镜头一致性是所有 AI 短剧工具的最大痛点，也是本项目提示词策略层最有积累的地方。
   - 方向：参考素材绑定的自动化推荐（现在靠用户手选）、跨镜头角色漂移检测纳入缺陷检查、首尾帧衔接自动化。
2. **一键成片自动化流水线（效率壁垒）**
   - 现状是"每一步都能做"，目标是"一章一键从剧本到成片草稿"，人只做审校和重生成决策。
   - automation/episode-orchestrator 已有雏形，值得升级为明确的章节级状态机（L4 项目，需 RFC）。
3. **成本与计费精细化（商业化生命线）**
   - 多 provider 价格差异大、废片重生成消耗真金白银。方向：按 provider 成本核算、废片不计费/折扣策略、用量看板。

## 5. What to kill?（该砍或冻结的）

- **不做**多租户/团队协作：单人创作者是当前用户画像，协作是伪需求。
- **冻结**新 provider 接入，除非现有 provider 停服或价格剧变——适配矩阵已够宽，边际价值低。
- **不做**前端框架层面的重构（状态管理库、组件库引入）：plain CSS + composables 模式运转良好。
- **停止**继续在类型/编译器严格度上投入——已满配，边际收益为零。

## 6. Moat（壁垒与加固）

**核心壁垒 = 短剧领域的提示词策略层 + 废片治理闭环，两者都以可测代码沉淀。**

加固方式：
- 每次视频质量问题的修复都必须落为策略函数 + 回归测试（已是惯例，保持）。
- 缺陷检查的判定规则持续积累领域知识（如"分身""字幕污染""物理违和"），这是竞品难以简单复制的数据资产。
- 保持 provider 无关性：策略层输出结构化意图，适配层翻译——避免被单一 provider 绑架。

## /ev 执行含义（R11 起）

- 攻向主线切换为第 4 节的三个方向，优先方向 1（小步：绑定推荐策略、漂移检测策略均可 L2 切入）。
- 方向 2 的章节状态机是 L4，触发前先写 RFC 到 docs/。
- routes/resources 补测试、db 顶层 await 等债务性任务降级为守轮备选。
